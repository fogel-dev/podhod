# Инструкции для агентов

## Проект

- Название проекта: «Подход».
- Рабочая директория — корень этого репозитория.
- Отвечай пользователю на русском языке, если он не попросил другой язык.
- Перед изменениями изучи существующий код и конфигурацию. Монорепозиторий: apps/web — React + TypeScript + Vite, apps/api — Go. Решение и границы описаны в docs/adr/001-monorepo.md.
- На фронте соблюдай FSD: app → pages → widgets → features → entities → shared, public API слайсов и запрет импорта соседних слайсов. Добавляй слои/сегменты по мере появления реального кода, без пустых заготовок.
- FSD-импорты контролируются ESLint правилом architecture/fsd. Используй alias @/ между слоями; вычисляемые динамические импорты бизнес-модулей запрещены.
- Не добавляй моки, фиктивные API, demo/seed-данные и временные продуктовые экраны. Данные HTML-прототипа остаются в design/ и не попадают в приложения.
- Вноси изменения в рамках задачи и проверяй их подходящими для проекта средствами.
- Не сохраняй секреты, токены и API-ключи в файлах репозитория.

## Продукт и обязательные требования

- «Подход» — mobile-first PWA для личного тренировочного процесса. Установка на домашний экран и рабочие push-уведомления обязательны для выпуска.
- Разрабатывай по этапам: требования и дизайн → техническая проверка PWA и архитектура → основа → функции → приёмка. Не реализуй весь backlog за один проход.
- Программа: период, количество тренировочных дней через выбор конкретных дней недели, упражнения по дням. Предусмотри явное копирование набора на выбранные дни.
- Сохраняй введённые упражнения в библиотеке для повторного выбора. В плане указывай вес (кг), количество подходов и целевые повторения; в истории сохраняй фактические значения.
- Календарь: отдельная вкладка и месячный календарь на главной. Показывай будущие и прошедшие тренировки, миниатюры фотографий стопкой. День открывает план или результат, заметки и галерею.
- Тренировка: последовательность упражнений, общий список и отметки подходов. Детали упражнения содержат вес, повторения, заметку и советы по технике из проверенного источника.
- Завершение подхода начинает секундомер отдыха; «Приступить к подходу» останавливает его. Сохраняй интервалы для итоговой статистики. Считай время по timestamp, обеспечь восстановление после сворачивания и перезапуска.
- Прогресс: выбор упражнения, графики фактического веса, подходов и повторений, краткая сводка. Не смешивай план и факт.
- Редактирование программы не должно переписывать завершённые тренировки. Предусмотри сохранение тренировки без сети и безопасную синхронизацию.

## Дизайн

- Сначала прорабатывай макеты и сценарии. Первая версия концепции находится в docs/design.md; макеты — в design/.
- Ориентир — ясность интерфейсов Apple: системная типографика, аккуратные отступы, спокойные цвета, мягкие тени и осмысленные анимации, особенно в календаре.
- Без стекла, glassmorphism, декоративных градиентов, шаблонных секций с бордерами и модного шрифта по умолчанию. Не превращай приложение в маркетинговый лендинг или плотный dashboard.
- Светлая и тёмная темы обязательны. Переключение плавное, с поддержкой prefers-reduced-motion и сохранением выбора.
- На Apple используй нативный системный шрифт. На Windows и остальных платформах используй локальный Onest из design/fonts (с кириллицей и лицензией OFL); не подменяй его Arial/Segoe UI. SF не поставляй без проверки лицензии. Не используй синтетический bold.
- Основной визуальный референс пользователя — Apple Fitness. Актуальное направление: нейтральный чёрный/серый, холодный индиго-фиолетовый акцент, плотная иерархия и умеренные скругления. Коралловая/молочная палитра предыдущей итерации отклонена.
- Текущие цвета и шрифты итерации 3 приняты пользователем. Не меняй палитру и типографику без нового запроса.
- Логотип принят пользователем: знак из трёх округлых вертикальных столбиков разной высоты слева и строго строчная надпись «подход.» справа. Не меняй его без нового запроса. Сохраняй точку, текущий шрифт и фиолетовый акцент знака. В макете знак использует цвет темы; геометрия хранится в design/brand-mark.svg.
- Избегай мотивационных слоганов, декоративного оформления вокруг принятого логотипа, надписей капсом с широким трекингом, огромных округлых панелей и пружинящих эффектов без назначения. Анимации должны объяснять переход/изменение состояния; вкладки переключаются сразу, детали открываются с направленным переходом.
- Важные действия доступны большим пальцем. Проверяй ширину от 320px, safe-area, экранную клавиатуру, контраст, фокус и зоны касания около 44px.
- Переходы между экранами не должны давать просвечивание, мерцание или краткое повторное появление старого содержимого под новым. Это обязательный критерий приёмки React-навигации; проверяй также быстрые повторные переходы и обе темы. Не переносить механизм клонирования экранов из раннего HTML-макета.
- twenty_first используй как источник деталей и референсов, а не готовой визуальной структуры всего приложения.

- После принятия пользователем разработки задачи Linear выполняй коммит и пуш всех относящихся к ней изменений. Сообщение коммита — на русском языке, с номером Linear и конкретным пояснением сделанного, например «EGO-10: инициализированы React/FSD и Go API в монорепозитории». До приёмки не коммить и не пушь эту задачу автоматически. При ошибке пуша сохраняй локальные изменения и сообщай точную причину; не отмечай синхронизацию выполненной.
- Не выполняй публикацию/деплой автоматически из задачи на макеты. Не создавай дополнительные чаты и не делегируй агентам без соответствующей инструкции.

## PWA и архитектура

- Проверь установку и реальную доставку push на целевых устройствах до завершения MVP. На iOS учитывай Home Screen установку и запрос разрешения по действию пользователя.
- Предусмотри HTTPS, manifest, service worker, серверную отправку Web Push, подписки и часовой пояс напоминаний. Разрешение запрашивай в понятном контексте, а не сразу при первом открытии.
- Не обещай точность фонового JS-таймера или push для отдыха. Таймер восстановления и тренировочные напоминания — разные механизмы.
- Основа backend — Go; зафиксирована ADR-001. Проект EGO-9 принят: PostgreSQL, приватное объектное хранилище, email-коды, Go worker и бюджетный VPS описаны в ADR-002 и docs/backend.md, docs/api.md, docs/deployment.md. Порядок реализации EGO-18–EGO-34 с ранней проверкой PWA EGO-8 — в docs/implementation-plan.md; актуальные статусы в Linear.
- Соблюдай приватность фотографий и тренировочной истории; не отправляй личные данные в поисковые запросы MCP.

## MCP

Используй реальные вызовы инструментов. Наличие инструмента в каталоге само по себе не подтверждает работоспособность подключения. При ошибке сообщай её и не выдавай невыполненный вызов за успешный.

### context7

- Для документации библиотек сначала вызывай `resolve_library_id`, затем `query_docs` с полученным идентификатором.
- Для официальной документации React при проверке подключения найден идентификатор `/reactjs/react.dev`.

### chrome-devtools

- Используй для открытия страниц и проверки приложения в браузере.
- Для проверки подключения можно открыть новую вкладку `about:blank` через `new_page`.

### twenty_first

- Ищи примеры UI-компонентов через `search`, например dashboard, KPI-карточки и графики.
- Перед использованием AI-генерации проверяй `get_usage` и поле `aiGenerationEnabled`.
- Если AI-генерация отключена, не вызывай её. Учитывай квоту получения кода компонентов через `get_component`.
- Поиск метаданных и получение кода — отдельные операции.

### linear

- Используй `list_projects` и `list_teams` для проверки доступных проектов и команд.
- Проект «Подход»: `P-EGO-1`, команда `EGO` (Egor Fogel).
- URL проекта: https://linear.app/egor-fogel/project/podhod-0fb97512cb40
- Перед изменениями задач проверяй актуальные данные через MCP.

## Проверенное состояние

На 10 октября 2026 года все четыре MCP успешно ответили на реальные вызовы. Это исторический результат проверки, а не гарантия текущей доступности.

У twenty_first на момент проверки был тариф `free`, две доступные операции получения кода за день, `aiGenerationEnabled=false` и нулевой баланс AI-кредитов. Проверяй актуальные лимиты через `get_usage`.
