# Реализованные серверные функции

Текущий проход: упражнения → программы → тренировки и исправления истории → календарь → приватные фотографии → прогресс. VPS/PWA, клиентская офлайн-очередь и полноценная синхронизация, push, экспорт/удаление аккаунта и эксплуатация выполняются позже. UI-сценарии остаются в родительских продуктовых этапах Linear. Готовность API не означает готовность всего приложения к выпуску.

## EGO-23 — библиотека упражнений

Реализованы GET/POST `/api/v1/exercises`, GET/PATCH `/api/v1/exercises/{id}` по существующему OpenAPI. Создание и изменения требуют cookie/Origin/CSRF, текущего X-Device-Id, Idempotency-Key UUID; PATCH дополнительно If-Match. Поиск по нормализованному имени, архив/восстановление, подписанная пагинация, стабильная сортировка UUID, чужие записи возвращают 404. Изменения и command receipt записываются с change_log в одной транзакции под блокировкой пользователя; повтор возвращает сохранённый результат, другой payload с тем же ключом — 409. Версия защищает от перезаписи между устройствами.

Таблицы exercises и technique_guides — миграция 003. Runtime API имеет только SELECT на technique_guides: пользовательские заметки не становятся проверенными советами. Публикация редактором: проверить HTTPS источник и соответствие конкретному варианту упражнения, сохранить краткий собственный пересказ, sourceTitle/sourceUrl, фактические sourceAccessedAt и reviewedAt, затем вне продуктового API выполнить параметризованную запись ролью владельца схемы. Не выдавать runtime credentials права редактирования таблицы. Будущие советы не публикуются до reviewedAt; при отсутствии материала techniqueGuide=null. Никаких предзаполненных упражнений или фиктивных источников нет.

Проверки на реальной изолированной PostgreSQL: повтор/повтор с другим payload, чужие ID, конкурентные PATCH (один успех/один конфликт), архив/поиск, границы страниц и привязка cursor к аккаунту, права на публикацию техники, число атомарно сохранённых receipts/changes. Общие Go tests/vet и совместимость OpenAPI проходят.

## EGO-24 — программы

Миграция 004 добавляет programs/revisions/days/exercises/targets/exceptions с составными FK владельца. Все девять маршрутов программ реализованы. Ревизии и их дети запечатываются при публикации; триггеры и права БД запрещают последующую правку и добавление строк. Копирование создаёт новую ревизию и отдельные ID, заполненные цели требуют replaceExisting. Пересечение периодов других программ проверяется под блокировкой пользователя. План вычисляется по effectiveFrom, weekday и исключениям; перенос убирает исходную дату и не занимает другой план. Архив ограничивает будущее без изменения прошлой ревизии. Timezone фиксируется для программы, прошлое расписание не редактируется; GET читает согласованный repeatable-read снимок.

Проверены на PostgreSQL: неизменяемость ревизии и запрет добавления дней после публикации, повтор создания, чужие ID, пересечение периодов, копирование/конфликт замены, просмотр прежней ревизии, перенос/занятая цель/отмена переноса, архив с сохранением расписания до границы. Проверены неизвестная timezone, границы даты и повторений. UI мастера отдельно в EGO-12.

## EGO-25 — тренировки

Миграция 005: workouts/revisions/exercises/sets/rest/events, одна active тренировка и одна недискардированная тренировка на исходную дату программы. Реализованы start, чтение списка/active/деталей и семь active команд: begin_set, complete_set, undo_last_set, correct_set, replace_active_exercises, finish_workout, discard_workout. REST start использует Idempotency-Key/X-Device-Id; команды — commandId/deviceId из envelope. Данные, событие, receipt и change_log атомарны, версия увеличивается один раз. Снимок имени берётся из выбранной ревизии, план/факт разделены. Старая сохранённая собственная ревизия допускается; сервер не заменяет её текущим планом. scheduledDate идентифицирует исходную дату программы, localDate — фактическую дату начала.

Время отдыха хранится в UTC timestamp, общее время вычисляется из отметок; фонового JS таймера для хранения нет. Complete открывает отдых, begin/finish закрывают его; финальный отдых входит в totalRest, средний учитывает только next_set. Finish требует явного skipRemaining. Undo разрешён до следующего begin; correction меняет факт без перестройки времени. Replacement не переносит/переписывает выполненные подходы и не добавляет фиктивный факт или проверенную технику. Смена программы не затрагивает снимок. Для начатой даты запрещена правка исключения расписания. Завершённые/дискардированные ревизии запечатываются; SQL триггеры защищают дочерние записи, специальная cleanup роль может удалить их при будущей очистке аккаунта.

Проверки PostgreSQL: гонка двух стартов, безопасный повтор start/finish, ownership, полный цикл complete/undo/begin/finish, skip confirmation, точные volume/duration/total rest/mean rest, SQL запрет правки завершённых фактов, saved program snapshot и защита replacement. Клиентское восстановление IndexedDB отдельно в EGO-28, экран — EGO-13. Исправление завершённой истории реализуется следующей EGO-26.

## EGO-26 — исправление истории

correct_result принимает полный исправленный результат и reason, проверяет факты и временную шкалу, создаёт новую sealed ревизию и атомарно переключает currentRevision/version. Время прежней ревизии также остаётся в БД. Дата и timezone истории сохраняются; verified technique берётся из прежнего снимка либо редакторского материала для выбранного собственного упражнения, не из неподтверждённого текста клиента. Интервалы не могут перекрывать подходы, иметь отрицательную длительность или ссылаться на отсутствующие факты. Чтение списка и отдельной прежней ревизии защищено ownership и repeatable-read снимком.

Реальная PostgreSQL: конкурентные correct_result дают один success и один 409; текущая сводка меняется, прежние вес/повторы остаются; доступны две ревизии; чужой аккаунт получает 404; runtime не может удалить прежние подходы или снять sealed с новой ревизии. Go tests и vet проходят. UI исправлений остаётся в EGO-13.

## EGO-29 — календарь и дневник

GET calendar (ровно один месяц), GET day, PUT/DELETE day note реализованы. Согласованный снимок объединяет выбранную ревизию расписания, исключения, фактические тренировки, заметку и реальные метаданные photos. На исходной дате переноса показан moved с целевой date, на целевой — planned/missed/started/completed и исходной sourceDate. Пропуск вычисляется по локальной дате программы; отмена отличается от пропуска. Сохранённые localDate не пересчитываются при смене timezone аккаунта.

Миграция 006 добавляет day_notes с версиями/soft delete и таблицу photos, у которой уже есть реальный потребитель — календарь и день. Загрузка байтов и обработка выполняются в следующей EGO-30, без фиктивных фотографий. Заметки используют If-Match (0 для создания), receipts и change_log; после удаления новая заметка получает следующую версию того же ID, старое устройство не перезапишет её старой версией.

Проверены на PostgreSQL: повтор записи, конкурентная правка, чужая заметка, delete/recreate, атомарный журнал изменений, source/target календаря без дублирования, размер месяца и invalid month, сохранность даты после timezone patch. Клиентский календарь остаётся в EGO-14, офлайн/sync — отдельные будущие задачи.
