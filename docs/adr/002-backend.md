# ADR-002: данные, API и бюджетный запуск бэкенда

Дата: 10 октября 2026. Linear: EGO-9. Статус: принято пользователем 10 октября 2026.

Уточнение 10 октября 2026: часть про email-код заменена [ADR-003](003-authentication.md). Первая версия — регистрация с почтой, логином и паролем, без отправки писем; внешние способы входа подключаются позднее.

## Контекст

Go и монорепозиторий приняты в ADR-001. Нужны приватные аккаунты, программы, фактические тренировки, календарь, фотографии, офлайн и Web Push. Пользователь подтвердил вход по email-коду и несколько аккаунтов; на старте пользователей единицы, приоритет — минимальные расходы.

## Решение

Модульный Go-монолит: HTTP API и отдельный worker из одного приложения и образа. PostgreSQL — единственное транзакционное хранилище и очередь задач. Приватное S3-совместимое объектное хранилище — обработанные фотографии и резервные копии. REST JSON под `/api/v1`, контракт OpenAPI. Same-origin cookie-сессии. Email-код через внешний почтовый сервис с транзакционными письмами.

Программа состоит из неизменяемых опубликованных ревизий недельного шаблона. Начатая тренировка содержит самостоятельный снимок плана и факты. Завершённая тренировка не меняется редактором программы; исправление результата создаёт новую ревизию результата с сохранением предыдущей.

Офлайн: IndexedDB, локальная очередь доменных команд, UUID команд, проверка версии агрегата, явные конфликты. PostgreSQL транзакционно сохраняет данные, результат команды, журнал изменений и фоновые задания. Отдельный брокер не нужен.

Первый production: один Linux VPS, Docker Compose, TLS reverse proxy, web, api, worker и PostgreSQL с постоянным диском. БД закрыта от интернета. Резервные копии находятся вне VPS. Нет автоматического деплоя в рамках проектирования.

## Альтернативы

| Вариант                        | Причина выбора или отказа                                                                                                     |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| SQLite                         | Достаточен для одного процесса, но PostgreSQL удобнее для одновременных API/worker, блокировок, отчётов и последующего роста  |
| Управляемый PostgreSQL         | Снижает обслуживание; рассмотреть при росте бюджета. Для единиц пользователей предлагаем собственную БД на VPS                |
| Redis / RabbitMQ               | Сейчас лишние сервисы: очередь с lease и повторными попытками помещается в PostgreSQL                                         |
| Микросервисы / Kubernetes      | Увеличивают эксплуатационные расходы без текущей потребности                                                                  |
| Фото в PostgreSQL              | Увеличивают БД и резервные копии; в БД только метаданные                                                                      |
| Фото на диске VPS              | Дешевле по числу сервисов, но усложняет восстановление и масштабирование; внешний object storage отделяет файлы от отказа VPS |
| JWT в localStorage             | Не требуется для same-origin PWA; серверные cookie-сессии проще отзывать                                                      |
| Автоматическое last-write-wins | Может потерять фактические подходы при двух устройствах; вместо него версии и явное разрешение конфликтов                     |

## Последствия

Один VPS — единая точка отказа, запуск предусматривает временный простой при аварии. Офлайн-клиент сохраняет тренировку независимо от доступности сервера. Работа с БД, обновлениями и проверкой бэкапов остаётся нашей ответственностью. Реальная установка PWA и доставка push подтверждаются на устройствах в EGO-8/EGO-16, архитектура этого не доказывает.
