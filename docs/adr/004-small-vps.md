# ADR-004: небольшой VPS и фотографии на его диске

Дата: 10 октября 2026. Linear: EGO-22. Решение уточняет ADR-002 после запроса пользователя: самый дешёвый VPS, единицы пользователей, мало фотографий.

Один VPS содержит PostgreSQL, Go API, worker, статический web и TLS proxy. На первом этапе нет managed PostgreSQL, Redis, MinIO и отдельного хранилища для рабочих фотографий. Минимальный целевой профиль — 1 vCPU, 2 GiB RAM, 25 GiB диска; возможность меньшего сервера подтверждается нагрузочным тестом, а не числом зарегистрированных пользователей. Сборка образов выполняется вне VPS.

В EGO-30 реализовать приватный filesystem storage за интерфейсом хранилища. Фотографии, миниатюры, временные экспорты и sync snapshots находятся вне web root, выдаются через API после проверки владельца. Сервер выбирает случайные ключи; клиент не задаёт пути. Запись через временный файл и атомарное переименование, отдельные staging/final ключи, ограничения размеров и квоты. Upload/read URL существующего контракта указывает на same-origin API; capability ограничена объектом, операцией, сроком и аккаунтом. Обязательная проверка сессии и владельца сохраняется. При переходе на S3 доменная модель не меняется. Сейчас файловые маршруты и пустые volumes не добавляются: они появятся с реальным потребителем.

Внешняя зашифрованная копия БД **и файлов** остаётся обязательной. Диск того же VPS, второй volume и snapshot у того же сервера не заменяют её. В EGO-34 настроить автоматический backup, retention, сигнал об отсутствии копий и восстановление на чистом окружении. До проверки восстановления выпуск пользователям не готов. Ключ расшифрования хранится также вне VPS.

Начальные лимиты production Compose: DB 384 MiB, API 256 MiB, worker 384 MiB, proxy 128 MiB, web 64 MiB; всего 1216 MiB без ОС, Docker и одноразовой миграции. Поэтому профиль не объявляется подходящим для 1 GiB. Ограничения обработки фото проверяются отдельно при EGO-30; GOMEMLIMIT не является ограничением всей памяти процесса. Нужен контроль свободного места (не менее 20%), квоты фото и ограниченные журналы контейнеров.

Компромисс: VPS остаётся единой точкой отказа, при восстановлении и выпуске допустим краткий простой. Миграция файлов на S3 и увеличение VPS потребуются при росте объёма или памяти worker. Покупка тарифа, домена и внешнего backup согласовывается по конкретной стоимости; текущая конфигурация сама ресурсы не создаёт.
