# ADR-001: единый репозиторий и границы приложений

Дата: 10 октября 2026. Задача: EGO-10.

## Решение

Один репозиторий `podhod`, приложения `apps/web` и `apps/api`. Фронт — React + TypeScript + Vite; backend — Go со стандартным `net/http`. Это соответствует запросу пользователя на единый репозиторий и освоение Go. Данные, PostgreSQL, хранение фотографий, авторизация и синхронизация ещё требуют решения EGO-9.

Npm workspaces управляет JS-зависимостями; Go имеет собственный `go.mod`. Не нужны Nx/Turborepo и общий JS-пакет ради одного фронта. Контракт API станет общей точкой интеграции после проектирования, а не общим импортом бизнес-кода разных языков.

## Независимый деплой

Каждое приложение имеет собственный Dockerfile, результат сборки и CI job. Один коммит может согласованно менять API и клиент, при этом выпускать их можно отдельно. При раздельных релизах контракт API должен оставаться обратно совместимым. Web обращается к `/api` на своём origin: в разработке через Vite, в контейнере через Nginx. Хостинг может заменить этот proxy своим ingress.

Compose обеспечивает локальный совместный запуск. Он не является готовой конфигурацией production: TLS, домен, постоянное хранение и push будут добавлены после соответствующих решений. Базу данных и хранилище не запускаем до появления реальных потребителей.

## FSD на фронте

Направление зависимостей: `app → pages → widgets → features → entities → shared`. Слайсы одного слоя не импортируют друг друга; вход извне через public API слайса. У `app` и `shared` нет бизнес-слайсов: внутри сегменты по назначению. ESLint проверяет код, React hooks и границы импортов локальным правилом `architecture/fsd` из `apps/web/tooling/fsd-rule.js`. Правило охватывает статические импорты, реэкспорты и динамические импорты с литеральным путём. Вычисляемые динамические импорты бизнес-модулей не использовать: их границы нельзя статически проверить.

Steiger 0.7.0 был проверен, но исключён: ошибка загрузки ESM-конфигурации в Node 22.20 и уязвимость GHSA-vfj7-8cjw-p6xm в цепочке micromatch/braces. Не фиксируем устаревший стек и не скрываем audit-ошибки. TypeScript 6.0.3 выбран для совместимости с typescript-eslint 8.71.1, который ещё не поддерживает TypeScript 7.

Сейчас существуют только `app` (корень и стили) и `shared/assets` (принятый шрифт). Остальные слои создаются при появлении настоящего кода, без пустых index, универсальных папок utils и заглушек. Страницы будут в `pages/<сценарий>/ui`, пользовательские действия в `features/<действие>`, предметные модели в `entities/<сущность>`. Общие визуальные примитивы — `shared/ui` при появлении первого реального использования.

Тема следует системной через CSS; `data-theme="light"` или `"dark"` позволяет явно применить тему. Токены анимации и reduced-motion заданы глобально; контрол переключения с сохранением выбора добавится вместе с интерфейсом. Safe-area учитывается конкретными layout-компонентами, а не padding всего body.

## Go

`cmd/api` собирает зависимости и жизненный цикл процесса. `internal/config` читает и проверяет окружение, `internal/httpserver` задаёт маршруты, HTTP-таймауты и liveness. JSON-логи через slog, завершение по сигналу с ограниченным временем ожидания. Доменные пакеты, хранилища и миграции появляются после EGO-9. Внешних Go-зависимостей сейчас нет, поэтому `go.sum` не нужен.
